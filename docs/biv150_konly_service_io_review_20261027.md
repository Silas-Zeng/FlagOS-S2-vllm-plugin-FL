This is a CPU/read-only review of seven **actual downloaded target files**, individually SHA-verified: 569,277 bytes total. Exact source plus original manifest are retained in `docs/evidence/konly-i8-qk-20261027/service-io-target-source-v1.tar.gz` (124,440 bytes, SHA `d9915caff7883cdcae6d04a9bf8df5212c82864be3c8af299b66f3c8f4414688`). The adjacent `service-io-source-review-v1.json` records the seven hashes and missing sources. SDK attention source separately remains audited SHA54c495. ## Layout and format boundary

Target `v1/attention/backends/triton_attn.py:294–335` returns semantic shape `[blocks,2,block_size,kv_heads,head_size]` for NONE and selects NHD/HND stride permutations. For **contiguous NHD**, block16/two heads/head128/BF16 yields shape `[P,2,16,2,128]`, strides `(8192,4096,256,128,1)` in BF16 elements. `unbind(1)` gives both stock K and V strides `(8192,256,128,1)`, with V byte offset8192 and total16KiB per page. These are derived NHD values, not an observation of the currently live service tensor. HND, layer packing, offsets or padding must be rejected or separately described from actual strides; shape alone is insufficient.

Target runner `v1/worker/gpu_model_runner.py:7081–7158` reads packing offsets/block strides, derives blocks from raw allocation/page bytes, asks the selected backend for shape/stride order and delegates the actual view construction to `_reshape_attention_kv_cache`. The latter is imported at line205 from `vllm.v1.worker.gpu.attn_utils`, which is **not among the seven files**. Thus its real storage-offset and padded-view implementation is still unreviewed. Target `v1/kv_cache_interface.py:160–200` budgets default page bytes as `2*block_size*kv_heads*head_size*sizeof(dtype)` plus built-in per-token-head scales/padding when those modes are enabled. `v1/core/kv_cache_utils.py:1350–1358` uses page bytes in block-count/allocation budgeting. Our private K-only payload continues to occupy the original16KiB allocation; active payload12,416B does not increase capacity.

Private K-only layout is Kcode bytes0..4095, FP32 Kscale4096..4223, reserved4224..8191 and original BF16 V8192..16383. Code strides are **bytes** `(16384,256,128,1)`; V strides are **BF16 elements** `(8192,256,128,1)`; scale FP32-view strides are `(4096,2,1)` with base1024. Stock BF16 tensor metadata cannot identify these bytes. A trusted allocation/layer/generation format descriptor, or equivalent explicit ownership contract, must dominate every read/write/fallback/copy before any page is encoded. A bare dtype or shape check is not that descriptor.

## Copy, sharing, prefix and Graph lifecycle

Target `v1/worker/block_table.py:136–166` swaps request **metadata rows** and computes/uploads slots; it does not convert or copy K/V payload. Kernel-block-ID remapping at lines185–202 likewise changes indices, not format. Preserve page-table/slot semantics, invalid/padded tokens and Graph-stable device pointers.

Target runner `gpu_model_runner.py:7226–7268` initializes/aliases caches, and lines7357–7366 register ordinary/cross-layer caches with KV transfer plus `copy_kv_blocks`. The actual transfer helper, swap/copy kernels and `_reshape_attention_kv_cache` body are outside this seven-file set. Repository `_C_ops_schemas.py:69–76` declares byte-block swap and logical reshape/gather operations; declarations alone do not prove their implementation preserves this format. Any logical K-only copy that omits scales is insufficient.

**A raw, complete16KiB page copy can preserve Kcode+scale+V without conversion**, provided source/destination formats and page strides agree, no bytes are omitted, and stream lifetime/ownership is correct. Repo `biv150_kv_page_copy.py:13–67` copies complete raw uint8 page runs; `biv150_kv_pitched_copy.py:12–67` fixes normal page size16384 and preserves every logical page. These are local private copy helpers, not proof they are the active service transfer path. Their bytes are format-transparent; the caller still owns format metadata, completion events and cache generation. A later capacity change would invalidate this16KiB reasoning and require new page-size/stride/allocation proofs.

Target `v1/core/kv_cache_manager.py:214–238,460–518` handles prefix lookup/free/eviction/reset; lines520–552 describe shared-prefix references. The physical pages may outlive one request. Encode once under a consistent cache-format lifetime; do not re-quantize encoded data on a prefix hit or mark a freed/reused page valid from stale host metadata. Sharing/aliasing and transfer must preserve both payload and the descriptor. Prefix hash construction/coordinator implementation is not in the downloaded set, so inclusion of format/generation in current cache identity is **unknown**. Either make format immutable for the whole relevant cache lifetime or prove compatible invalidation/keying before mixing formats.

Existing `biv150_compute_order.py:53–103` pins the actual normalized→GQA→generic wrapper chain; its runner scope rejects transfer/shared-layer/cross-layer cases at lines157–173. Preserve those established restrictions. Do not install a new payload by relying on a lower wrapper's ordinary fallback. Graph tests must change Q, K/V/slot/table/length metadata, poison outputs and encoded/Q temporaries, and demonstrate eager/Graph/side agreement with matching generation and stream ownership. The stock diagnostic bridge avoids this stored-format risk because it never changes the stock cache, but its future hook still needs separate validation.

This map establishes concrete source obligations and gaps, not completed service IO coverage. First complete/verify the relevant native readers and writers, then a reviewed format-aware opt-in service seam, then real105-model accuracy and official service acceptance. No proxy precision threshold is relaxed and no component ratio is promoted to service gain.
