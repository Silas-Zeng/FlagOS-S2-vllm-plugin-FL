# BI-V150：默认启用原生 GQA 的 V 等待重叠

依赖已合并 PR92，在原 N64/S2、N32/S4 路径中延后 V 的完成等待，让 K/QK 与 softmax 覆盖部分等待，在 PV 消费前同步。离线构建实际启用自研宏1实现，QK/softmax/PV 算术、BF16 舍入、分段和采样参数保持原样；不包含已停止的 mixed 扩覆盖。

三个生产文件逐字复用受测源包 `58a2fc96`：CU 默认宏、离线构建器、helper 实际启用标记。当前 main `4229b48` 相对受测基线只增加 PR94 的诊断工具和记录，生产实现未变。

| 原官方验证 | PR92 基线 | 本候选 | 结论 |
|---|---:|---:|---|
| 4K 四轮弃首均值，总 tok/s | 6481.226667 | 6627.816667 | 观察 +2.261763%，1024 请求成功 |
| 16K 四轮弃首均值，总 tok/s | 4826.446667 | 4832.660000 | 观察 +0.128735%，512 请求成功 |

4K 原四轮为 5481.01 / 6441.35 / 6721.46 / 6720.64；16K 为 4269.60 / 4834.45 / 4832.36 / 4831.17。两档各自与基线 KV 容量相同（548336 / 548288），起始 DB 相同。S2/S4 完整组件的位型、FP64、尾页、换值 Graph 和 side-stream 检查通过。实际模型路径、源码/两库身份、DB 恢复与进程清理通过。

这是单组官方性能观察，16K 小差异不称稳定幅度。105题仍使用原采样，单题变化不解释为准确率提升。105的通用 stack 读器缺少 `compute_order_selected`，与旧基线105相同；GQA自身两shape均捕获，但启动 capture 不代替逐题分支覆盖。不为发布重复已通过且未变的检查。
