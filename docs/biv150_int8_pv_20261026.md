# Direct integer PV with BF16 K and token/head INT8 V

This is a different bounded hypothesis from closed PR49(register dequantized BF16 K/V) and PR54(software E4M3 reconstruct-before-BF16-PV). Retain BF16 K/QK and original softmax/reducer. Fold each cached V token/head scale into the positive unnormalized probability, dynamically quantize that weighted probability to0..127 per row and32token group, and multiply it by cached signed INT8 V using an actual integer dot. Restore its FP32 scale into the existing accumulator. The128-dimensional V tile is never expanded to BF16/FP32 before the dot.

Tile32 covers two independently mapped16token pages; it is also different from prior negative BF16 multi-page variants because the PV operands and register/data costs differ. This is an untested scheduling hypothesis, not evidence of supported hardware shape or speed. Both P and V are deliberately approximate. Define probability half-up and signed V half-away rounding explicitly; neither follows the separate FP8 codec's RNE convention.

CPU-only scalar75cases verify each token is covered exactly once across segment boundaries and that an independent global normalized-probability formula agrees with a streaming-max/sum segmented implementation in normal finite FP64 domains(max error4.44e-16). Underflow floors/device FP32, actual integer-dot support, writer consistency, real tiled output/Graph and all performance remain unvalidated. These checks prove algebra, not model accuracy.
