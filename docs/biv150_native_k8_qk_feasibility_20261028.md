# Native page16 with K8 / INT8 QK: CPU feasibility only

Base is actual fresh-fetched/API-confirmed mainb3b87d2a1c13448bd8c6bc24e8045c0458b8b9dd (PR92), not older DAC1. This adds no CUDA kernel, installer, package import, device compile/launch, service switch or queue. No Torch/Triton/Numpy is imported. It neither modifies89/91/92 nor treats their scores as a matched baseline. K8's old6327.95/4905.64 and team native-BF16 report are different source/protocol observations; no combined gain is inferred.

Dependencies are PR92 native BF16 page loop/PV, PR79/83 RN32/RNE K-codec+append, PR86 typed-view contract and future PR89 service/all-reader lifecycle. PR91 compact12544 is separate/unverified here. Current CPU ABI deliberately admits only full16KiB page layout; any future compact adapter must bind its actual views/strides/version separately.

The precise proposed structure preserves page16,64-thread one-warp CTA, N64/S2 orN32/S4, D128/GQA8, current BF16 PV/SME-V/probability BF16 rounding, F32 online max/sum/FMA, partial outputs and reducer. Only QK becomes signed-I8/I32 with original BF16 Q quantized in the CTA using the same RN32/RNE v2 as K. Scores become I32→F32×(Qscale×Kscale)×original softmax_scale_log2e before the unchanged softmax/PV. Four K32 native QK MMA calls replace eight BF16 K16 calls in this declared logical geometry; actual compiler output/latency is not verified.

Actual local SDK includes resolve through `mma.h`/mapping/ILU CRT into `iluvatar_mma.hpp`. Header identities are recorded without redistributing proprietary headers. Its actual signed-char `mma_sync_tcu` calls `__ivcorex_matrix_mad_i32x4_i8x8`; no guessed8-bit SME builtin is used. The first potential implementation would use ordinary coalesced32-bit global K loads and an independently described2KiB shared scatter, retaining stage8KiB and original V region at+4096B. This gives up b3's efficient SME-K load and introduces instructions/synchronization; it may lose despite less payload. The model is not an implementation of those device operations.

CPU byte/lane model independently decomposes64-D K col-image panels and the I8 Q row image, proves both2048-byte images bijective and proves actual declared TCU word addressing retrieves the expected coded matrices. It reconstructs4-head-byte I8 A words from the original2-head/lane Q reads using two pair shuffles, so no additional global Q read is silently assumed. Input head pair(2*g,2*g+1) differs from C output(g,g+4,g+8,g+12). The source-based C coordinate relation and independent head-scale ownership are tested across all64 lanes/four components. FragmentC<signed int> is actually backed by unsigned words: negative scores require signed bit interpretation before F32 conversion. The signed I32 bound128*127²=2064512 is safe and exactly representable in F32.

The old generic BF16 fragment layout, k_half_index and SME16 K descriptor are not reused. The SDK's legacy `load_matrix_sync` also reads its prepacked coordinate layout and ignores ldm; it cannot accept an ordinary NHD pointer merely because an ldm is passed. These are concrete blockers to a dtype-only substitution. The declared typed TCU path has A/B8-byte and C16-byte storage, but this does not prove device C++ ABI, register count, occupancy or native fragment execution.

Full-base scale address is layer_page0+page*16384+4096+slot*8+head*4; already-offset scale views reject. K I8 strides are16384/256/128/1, V BF16 remains8192/256/128/1 from its already-offset pointer. Nonzero layer base and last-page/all-slot addresses are checked. The current native BF16 `.cpp`/runtime admits BF16 K only; encoded bytes must never enter it. Any future candidate needs a new typed operator/identity and a correct private K8 fallback on prelaunch rejection. Unknown encoded data must not reach a stock BF16 fallback; postlaunch errors propagate.

Accounting per KV head/page: old K4096+V4096=8192B; K8 K2048+token/head F32 scales64+V4096=6208B, ideal payload−24.21875%, before transactions/Q/scratch/control. It is not a full-kernel or service bound. Q quantizes4096/8192 BF16 values per sequence inS2/S4 due to repeated segments, including peak reduction, exact RN32 divisions/RNE, shuffle repacking and C-scale ownership. No persistent Q-code cache is claimed. Register pressure includes32 FP32 PV accumulators, Q fragments/scales and quantization temporaries; sizeof accounting cannot establish an improvement. Stage stays8KiB rather than claiming shared memory saved.

Append must use the direct stride-aware K8 writer, never old BF16 writes into live encoded K. Per new token, source K/V reads1024B are common; output changes from1024B to Kcode256+Kscale8+V512=776B, plus codec arithmetic and all dispatch/copy costs. No full-cache reencoding or extra active-page staging is needed for per-token/head K scales. Existing all-reader, copy/swap/prefix, reallocation/epoch and Graph lifecycle prerequisites remain; component append qualification does not establish a deployed cache service.

The native W8A8 row quantizer has half-away rounding and different scale arithmetic and is not this RN32/RNE codec. Device RN32/RNE implementation/FTZ/half boundaries still require exact native intrinsic verification and later device conformance. The CPU rational oracle is kept independent. Prototype tests include zero, signed/head markers, random finite BF16-representable values and BF16 subnormals; valid slots0/1/7/15/16; signed-negative scores; all fragment words and output coordinates. Eight ABI mistakes reject, including nested bool/float values. The old input-pair Q-scale mapping has a separate negative control. Pinned source/helper bytes are checked before the CPU model.
