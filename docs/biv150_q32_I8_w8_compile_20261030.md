# Private Q32 I8 w8/stage1 compile scout

Base is exact team main899ce77470b0b539aebc108fd122f668c2d5894d. No official
upstream update, production import, installer, environment flag or default path
changes. Root owns later scheduling; this preparation does not invoke devices.

This asks one question: how does the existing BF16-Q → RN32/RNE QCode → native
I8-QK/BF16-PV reader lower with w8 instead of w16? BM256/BQ32/K64, stage1,
Q2048/N1, grid65×2, codec, masks, softmax, P rounding, stores and complete GPU
source bytes stay unchanged. K/V use the existing 16KiB carrier, not compact:
K I8 strides16384/256/128/1, V BF16 strides8192/256/128/1 and offset4096 BF16,
full-base FP32 scale. The allocator, kwargs mapper and artifact exporter are
the existing reviewed compile helpers, not a new numerical framework.

The default entry is stdlib-only. Explicit `--compile-only` makes one raw w8/s1
warmup, empty CUDA allocations and handle loading, with zero attention/writer/
encoder launches. Context/empty allocation work is explicitly recorded. It
requires clean exact HEAD/main899 production bytes, installed SDK/helper/JIT/
codec pins, Root serial ownership, closed9031, empty visible native PID query
and conservative preCUDA memory observation. Invisible PIDs do not prove idle;
Root must first close the actual previous job. No process is killed.

The source derives the previously reviewed zero-launch driver through exact
counted edits and inverse. Required Git objects (no historical raw data):

844a69f10539c551500e29e2304061aef7d8671b driver749a662b…/kwargs b82f517b….

No existing w16 hoist grammar or override is applied. Actual source/TTIR/TTGIR/
LLVM/ASM/cubin plus raw metadata and typed compiler inputs are exported before
the private recorder can reject unknown metadata. The normal recorder saves
complete ABI/options hashes and the actual objects' handle resources. Nonzero
actual spill is retained; compiling does not qualify it or manufacture zero.
The original production recorder is unchanged. Compiler override knobs remain
disabled, and any missing/unknown artifact is preserved rather than licensed.

After the first real compile, inspect whether QCode operand reads are outside
KV, shared-bank publication/lifetime, actual native I8 QK and BF16 PV, complete
ABI/options, final ELF registers/scalar spills/shared and actual instruction
paths. If Q remains inside KV, preserve that result and separately decide on
a w8-specific hoist transform; the old w16 receipt grants nothing. Larger
per-thread live fragments may negate fewer warps. No occupancy or gain follows
from source or a register count. Any subsequent benchmark must compare against
current actual-hoisted w16/S1, not a raw unhoisted control, and keep original
codec/FP64/BF16-quality/Graph/readonly gates. No numeric or timing entry is added.

Historical BF16 BM256/w8 component gains were against an older BF16 control;
they are not I8 evidence. PR87 BM128/BQ16/w8 I8 still read QCode inside KV and
was not timed. Negative BM64/w8, BM128/w4 and I8 Q64 trials are not repeated.
All actual-hoist/resource/numeric/Graph/performance/model/service qualifications
remain false. One raw compile is the proposed next falsifier, not a service claim.
