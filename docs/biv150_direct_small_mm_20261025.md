# Direct selected-vendor small BF16 MM route

This experiment depends on PR51's self-developed masked16x64/K128/4warp/1stage kernel. The GPU kernel AST is byte-structure identical to that qualified implementation; this fact does not validate the new binding. Team main was rechecked at0915f01 before creating this independent branch.

PR51's opaque linear integration recovers the concurrent question and passes101/105; its first4K score is5520.23 total tok/s, TTFT3402.46ms,256/256, with16K/control still running. The new binding aims to preserve the original framework/Inductor prefill path and output allocation rather than inserting an opaque linear op for every row size. Those existing results belong to PR51's linear binding and must not be assigned to this route.

Enable only with VLLM_FL_BIV150_STABLE_SMALL_O=1 and VLLM_FL_BIV150_STABLE_SMALL_O_BINDING=mm. Default remains the previously tested linear binding. On audited TP1 MiniCPM/default CUDA GEMM dispatch, the new route checks exact installed FlagGems MM source SHA4c2e23da..., verifies both already-bound mm/mm_out functions use that module's globals, then wraps only _launch_mm. M1–8, BF16, the four exact geometries and supported dense-transpose RHS/output strides select the same self-developed kernel into the original caller's output. Larger rows and every unsupported scope call the original vendor launch with identical arguments and return value. Framework vendor selection remains in place; compressed native INT8 gate and logits are untouched. GPU launch errors propagate without a fallback retry.

CPU-only checks pass32 positive routes,11 fallback scopes, source/symbol rejections, exact pointer-stride mapping, launch-error propagation and binding-aware compile-cache identity. The feature-off cache identity is binding-neutral. These use isolated mocked tensors/modules and do not prove a GPU binding or model recovery. Initial test setup required correcting mock context order; no GPU was used. No installation, additional GPU work, model precision or performance test has run for this binding.
