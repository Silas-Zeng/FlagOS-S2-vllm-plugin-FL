# Default-OFF NativeK8 natural mixed-prefix candidate

Base is team main a455a3de364051fbea80226870c239de3a48e716, last independently fetched by Root on 2026-10-29. This candidate has no device, numerical, throughput, precision or service qualification.

Current mixed prefixes D31/D63 enter private K8 Triton with S8/S4. The accepted 8b86 Native adapter accepts only N32/S4 and N64/S2. The new host wrapper admits exact N31/S4 and N63/S2 as well as the old host shapes, while reusing the accepted CUDA and codec **byte for byte**. No new GPU valid_rows argument or query/length padding is introduced. A fresh independent Torch operator namespace is used; the actual compiled SO and dual-library symbol/stub binding still require review.

The production hook remains OFF unless `VLLM_FL_BIV150_KONLY_MIXED_NATIVE=1`. It also requires the original owned16KiB encoded runtime and accepted Native parent, rejects compact storage, and requires fixed actual SO/consumer/full-step SHA pins. These pins intentionally remain `None`: both installation and the compile fingerprint currently reject ON. No fake library identity or completed device receipt is stored in production.

The natural-prefix wrapper keeps its original eligibility, Graph NONE/capture boundary, current stream and serial decode-before-prefill order. Only its decode metadata can be replaced, after writer ownership and epoch validation. The new metadata narrows the original width16 scratch segment dimension to S4/S2 and changes its segment count together. Its lengths, block table, query offsets and slots retain their original tensor identities; the original decode and suffix metadata are unchanged. The existing `_pick_segments` then clamps to that same count for both producer and reducer.

The views are **not packed/contiguous across heads**. Partial strides remain `(32768,2048,128,1)` and scalar strides `(256,16,1)`. Native receives these actual strides, and the original reducer receives the very same Tensor objects and stride arguments. No reshape or smaller physical pitch is fabricated. The CPU test executes the original producer and reducer launch AST with opaque recorders, checks every valid row/head/segment address, and verifies output `[0:D)` ends exactly where prefill output `[D:total)` begins.

A scoped forward ticket binds entry, row count, segment count, input/scratch geometry, host thread and current stream. Only its one producer call may use the new operator; no ticket means the original Native/Triton path. Errors after a producer or reducer are propagated without retry. N32/N64 retain the original 8b86 adapter, and unsupported shapes retain original metadata/routing. Original writer, CUDA/codec/math/reducer code, model runner, sampler, official CLI and benchmark are unchanged. Compile fingerprints distinguish the feature and pin its future actual qualification; the C3 mixed-source pin is updated to the exact changed wrapper. Every shipping host edit reverses byte-exactly to a455.

## CPU validation

Run without importing Torch/Triton or starting a device:

```sh
python tools/check_biv150_native_k8_mixed_cpu.py
python tools/compile_biv150_native_k8_mixed.py
python tools/probe_biv150_native_k8_mixed_component.py
```

The first check covers four N31/N63 × Qpitch2048/2560 cases, 12 rejected/no-retry mutations, unchanged Native32/64 and unknown-shape fallback, source inverses, and the actual fixed94db helper's compile-fingerprint regression. CPU opaque library/receipt fixtures are explicitly labeled; they are not real library loading or GPU evidence. Python3.12 and3.14 produced byte-identical CPU report SHA `9a528fd21a2277291ef677b3ab72a7d25bb717828e58e62a080ffc6c93ae452e`.

Selected local CPU results are in `docs/evidence/native-k8-mixed31-63-20261029`. No new device raw data is included. Two historical checks are preserved with their limits: the old b3 encoded-tail checker fails the same worker-import assertion on parent a455 and this child; the old identity-only Native service checker rejects the deliberately changed fingerprint source. Neither historical checker was weakened. The new source inverse and actual old-Native routing regression cover the changed scope; these failures are recorded in `legacy-check-boundary.json`.

## Next component stage

The runnable device entry in this first freeze is compile-only:

```sh
python tools/compile_biv150_native_k8_mixed.py \
  --compile-only --root-owned-exclusive --out <fresh-absolute-output-directory>
```

Root alone coordinates and executes it. The tool preserves actual compiler output, LLVM/ASM and SO, and does not launch an attention/codec/reducer kernel or allocate input arrays. Library registration is not a claim of zero CUDA API activity. It imports the same accepted CUDA files; native symbols/resources and new registered host-op binding must be checked on the **actual** produced SO, including coexistence with8b86.

The component contract frontend is CPU-only. A GPU numeric runner is not implemented in this initial freeze; it must follow actual-object admission rather than pretending that a plan is a successful test. Required controls are:

- D63/P1985/KV4096 and D31/P2017/KV16384, totalQ2048, valid prefill tables and unchanged original prefill reader.
- Performance baseline A is current TL63/S4 or31/S8. Candidate C is Native63/S2 or31/S4. Same-S TL is diagnostic B, never relabeled as the shipping baseline.
- Same-S accepted8b N64/S2 or N32/S4 with one extra zero-length row is an additional bitwise reference for valid31/63 rows. Its padding preparation is reference-only; all preparation actually required by the candidate remains in candidate timing.
- Keep original INT64/FP64 hard gates and every BF16 proxy result. Different-S A/C is not required to be bitwise; same-S references preserve O/M/L/final bitwise checks and separate unused-row/segment/output guards.
- Include real metadata/view setup, all-token append/codec, producer, reducer, unchanged prefill and actual stream dependencies/completion in complete-step timing. Reference-only or diagnostic work must not be hidden inside a claimed candidate saving.

PR85 already tested Triton mixed31/63 mappings but had no paired-prefill timing/service qualification; its poisoned prefill table cannot serve as this full-step fixture. PR95 tested stock-BF16 N48/N56, not this K8 path. No historical number is transferred to the new candidate. Only an actual complete-step improvement should lead to current-main service coverage, official105 and original warmed4K/16K acceptance.
