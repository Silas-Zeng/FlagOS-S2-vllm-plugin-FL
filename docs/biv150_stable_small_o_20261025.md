# BF16 small-row O projection stability experiment

On the personal BI-V150, the existing FlagGems O projection at M2, K=N2048 produced multiple different finite outputs for unchanged inputs:32/80 calls exceeded the independent FP64 tolerance on the default stream,21/80 on a side stream. Graph/eager equality also failed. The vendor BLAS diagnostic control was stable and passed all160 calls. These are the same real weights and sliced independently verified input/oracle rows from the prior M8 fixture; the original RNG-reconstruction caveat is retained. This is evidence of an operator fault, not yet proof that it causes the native-on mixed model failure in PR50.

The new self-developed BF16 kernel uses a masked16x64 tile, K128,4 warps and1 stage; FP32 accumulation and one final BF16 rounding. It keeps the original weights and does not quantize. The direct-out seam permits the same output buffer as the faulty baseline in component checks. The functional custom op is tested separately, and keeps runtime M branching inside its CUDA implementation to preserve vLLM's dynamic row contract.

Serving integration is default-off (VLLM_FL_BIV150_STABLE_SMALL_O). It targets only TP1 MiniCPM BF16 self_attn.o_proj, M1–8; larger rows retain FlagGems mm inside the functional custom op. Other projections and native gate remain unchanged. New source/feature identity enters compile-cache semantics. The strict compute_order runner pin is updated with the worker installer; CPU reconstruction verifies the previous runner is otherwise byte-identical.

The initial O-only kernel passed960 independent FP64/changed-input Graph checks across M1,2,8, direct-out and functional routes and two streams. M1/M8 component timing was approximately1.28x/1.61x the original out route; this is not a serving speedup. In same-source76b59a4 service comparisons, native remained enabled: both small-O off and on failed the concurrent long question with1024 output tokens and no visible answer. The on arm selected M2 as well as M1/4/8, and lost96 KV tokens (547536 versus547632). Full accuracy was correctly skipped. O alone is therefore not a demonstrated recovery.

A follow-up real-weight M2 CPU FP64 probe distinguishes functional linear from mm(out=...). O/QKV/down functional routes were stable in96 checks each while their out routes failed. The uncompressed layer0 gate/up functional route failed28/48 and30/48 calls on default/side streams; its out route passed. Logits passed both routes. These results do not identify which compiled serving buffer fails, but invalidate treating a faulty out route as proof that its functional serving counterpart fails. Native residual gate separately passed576 CPU INT64/changed-Graph checks for M1,2,3,4,8,16.

The next bounded variant extends the self-developed masked kernel only to uncompressed BF16 gate/up alongside O, still M1–8. Compressed native gate remains unchanged. Larger rows now call the exact original default_unquantized_gemm F.linear route; installation rejects batch-invariant or other platform dispatch. The original SDK dispatch and default GEMM implementations were inspected directly. This variant awaits GPU component and concurrent model validation. No105-question pass, fixed-workload gain or merge claim. Teammain remains0915f01; no official-upstream upgrade.


The expanded O+edge-gate variant dcaa66d passed3072 own CPU FP64/changed-Graph calls across all M1–8, both projections and both functional/out routes/streams. Same-source native-on model off/on still both failed; M2 O and edge-gate selection was verified, accuracy was skipped, and both services cleaned up. The v3 harness initially failed before starting any service due a helper import path; v4 fixes that harness path without modifying the frozen runtime.

A read-only inspection of the real on-model Inductor cache then confirms QKV/down lower to extern_kernels.mm(..., out=buf), including weight views(2048,2560) and(6144,2048). Thus stable eager functional counterparts do not qualify compiled QKV/down: their previously faulty out route is present in the actual model. The next bounded variant extends the same masked kernel to QKV(2560,2048) and down(2048,6144), with K128 looping over the actual K. All four shapes preserve the default framework linear fallback above8 rows. The compressed native gate and logits are untouched. Added shapes require independent FP64 and changed-Graph checks before another model run. No model recovery or throughput acceptance is claimed.
