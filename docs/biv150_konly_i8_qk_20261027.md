# Private K-only I8 QK primitive

This bounded experiment keeps V as the original BF16 bytes and studies only
logical `8x128 I8 @ 128x16 I8 -> I32 -> FP32(sQ,sK)`. It does not implement a
decoder, prefill, service hook, GPU quantizer or timing benchmark. Production
`vllm_fl` and `csrc` remain unchanged from team main56f1838.

The old direct-I8-QK experiment0e3d707 measured0.7804x/0.7787x, but also encoded V
as I8, converted its codes to BF16 and weighted P by Vscale. It is a related
negative result, not this exact K-only/original-V dataflow. Its host passed ROWS8;
there is no evidence that it expanded logical softmax/PV to16 rows. PR55's native
I8 PV is also a different experiment. No kernel internal MMA C-component pruning
or terminal slicing is proposed here.

Default verification uses the Python standard library only:

```
python3 tools/check_biv150_konly_i8_qk_cpu.py --out docs/evidence/konly-i8-qk-20261027/cpu.json
```

For finite BF16 vectors, one token/head scale is1 for an all-zero vector;
otherwise `RN32(max(maxabs/127,2^-126))`. Codes are nearest/even of the exact
value/FP32-scale ratio, clamped to[-127,127]. This fixes the mathematical codec;
no claim is made that a future GPU approximate divide implements it exactly.
Inline-Q and separate-preQ producers are deferred. The latter would remove split
duplication while adding a launch, temporary IO and Graph lifetime costs.

The integer oracle uses independent Python integer sums. The numerical oracle
reconstructs each quantized operand and sums FP64 products with `math.fsum`.
The primitive score order is `RN32(RN32(float(raw_i32)*sQ)*sK)`; invalid columns
store raw zero and score-inf. No softmax is executed for an empty tile. FP32
scaled fixture overflow is rejected. CPU IEEE checks do not simulate target FTZ.

The mixed page retains its original16384-byte physical allocation: Kcodes at
0..4095, FP32 Kscales4096..4223, untouched padding4224..8191, original BF16 V at
8192..16383. Active payload12416B is not reclaimed capacity. Address multiplication
uses i64 before physical page strides. Sources are BF16 vectors and the encoder
creates a new destination; it never compresses overlapping live K storage.

The prepared entry point defaults to the same stdlib CPU checks:

```
python3 tools/bench_biv150_konly_i8_qk.py
```

Only the root agent's later serial target run may opt into either command below,
from a clean frozen checkout. Neither command has been run for the fixed version:

```
python3 tools/bench_biv150_konly_i8_qk.py --compile-only --commit "$(git rev-parse HEAD)" --out /path/to/fresh-compile-directory
python3 tools/bench_biv150_konly_i8_qk.py --run-gpu --commit "$(git rev-parse HEAD)" --out /path/to/fresh-device-directory
```

The entry checks the audited SDK JIT hash, target corex/arch71/warp64, clean frozen
source and unchanged production tree, and uses an isolated cache under the fresh
output directory. Compile-only allocates device arguments and compiles the
primitive without launching it; pre-launch resources never count as loaded proof.
GPU mode rejects a busy device/service instead of waiting or queueing.

Prepared device checks cover36 cases per pattern, including all tails0..16,
shuffled pages/both heads, integer extrema±2064512, zero rows, and three changed
Q/K/scale/page/head/tail patterns. Eighteen eager/changed-poisoned Graph checks
across default and side streams require exact integer outputs and bitwise agreement
with the explicit IEEE FP32 score order; the independent reconstructed-operand
FP64 error is also reported on the CPU. Any FTZ/rounding mismatch fails this
strict fixture contract, with no tolerance switch. Output guards, poisoned inner
buffers, every packed input byte and original V bytes are checked. V is not read
by a PV consumer here: its layout/raw preservation is a distinct contract.

Actual TTGIR/LLIR/ASM/cubin are retained under their real compiled hash. The
mechanism gate checks signed-I8 M8/K128/N16, K32, exactly four native calls and
machine MMAs, a complete four-component C chain, and score casts at the exact
`raw.to(float32)` AST call site. Cast element counts and ISA opcode frequencies
are recorded without turning them into a latency estimate. Post-launch runtime
n_regs/n_spills/shared must all be known for the primitive result to pass; unknown
resources are recorded explicitly. Zero n_spills is not an independent SGPR-spill
proof. No resource equality with a full decoder is asserted.

The expected four I8 MMAs remain a prediction until actual candidate IR exists.
The checked-in SHA-pinned PR55 primitive IR is only a wrong-geometry negative
fixture for the auditor. Its old8x32@32x128 shape cannot certify this kernel.
CPU evidence currently covers1012 rounding cases,306 page/head/tail references,
108 prepared fixture cases and23 rejections, including poisoned cache payload and
FP32 overflow; it also proves the metadata/input patterns differ and source/V bits
are preserved, including signed zero and BF16 subnormal/maximum values.
No candidate GPU, performance, model precision or service qualification has run.
No timers, throughput benchmark or automatic queue are included.

The first actual compile of frozenf26e418 stopped in semantic.py before native
lowering: an I32 zero accumulator was passed while tl.dot's default output dtype
was F32. This is a missing API keyword, not a K32/M8 hardware or performance
negative. The primitive now explicitly requests `out_dtype=tl.int32`; CPU AST
regressions reject missing output dtype, F32 output dtype and F32 accumulator.
The old source/log and all six original file hashes are preserved under the
compile-v1 failure evidence; the original raw directory is untouched. No new
compile/GPU run was performed for this fix; numerical/reference math is unchanged.

Two fresh git-fetch attempts failed explicitly (receive timeout, then connection
timeout). Authenticated API rechecks confirmed team main56f1838 before branch
creation and the initial commit. This is not reported as a successful fetch or
an upstream SDK change.

Any future service change requires every writer and all2D/3D consumers, current
Q32/multi2/generic prefill, prefix/suffix/carry/copy, typed ownership, metadata and
Graph to agree on the representation. BF16 wrapper metadata cannot identify raw
codes. Existing mode2 or a decoder-only hook does not implement that contract.
Any component tolerance is separate from intended quantization error and the
105-question/model/official throughput gates.
