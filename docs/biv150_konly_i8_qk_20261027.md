# Private K-only I8 QK primitive

This bounded experiment keeps V as the original BF16 bytes and studies only
logical `8x128 I8 @ 128x16 I8 -> I32 -> FP32(sQ,sK)`. It does not implement a
decoder, prefill, service hook, GPU quantizer or timing benchmark. Production
`vllm_fl` and `csrc` remain unchanged from team main56f1838.

The old direct-I8-QK experiment0e3d707 measured0.7804x/0.7787x, but also encoded V
as I8, converted its codes to BF16 and weighted P by Vscale. It is a related
negative result, not this exact K-only/original-V dataflow. Its host passed ROWS8;
there is no evidence that it expanded logical softmax/PV to16 rows. PR55's native
I8 PV is also a different experiment. No kernel internal MMA C-component pruning
or terminal slicing is proposed here.

Default verification uses the Python standard library only:

```
python3 tools/check_biv150_konly_i8_qk_cpu.py --out docs/evidence/konly-i8-qk-20261027/cpu.json
```

For finite BF16 vectors, one token/head scale is1 for an all-zero vector;
otherwise `RN32(max(maxabs/127,2^-126))`. Codes are nearest/even of the exact
value/FP32-scale ratio, clamped to[-127,127]. This fixes the mathematical codec;
no claim is made that a future GPU approximate divide implements it exactly.
Inline-Q and separate-preQ producers are deferred. The latter would remove split
duplication while adding a launch, temporary IO and Graph lifetime costs.

The integer oracle uses independent Python integer sums. The numerical oracle
reconstructs each quantized operand and sums FP64 products with `math.fsum`.
The primitive score order is `RN32(RN32(float(raw_i32)*sQ)*sK)`; invalid columns
store raw zero and score-inf. No softmax is executed for an empty tile. FP32
scaled fixture overflow is rejected. CPU IEEE checks do not simulate target FTZ.

The mixed page retains its original16384-byte physical allocation: Kcodes at
0..4095, FP32 Kscales4096..4223, untouched padding4224..8191, original BF16 V at
8192..16383. Active payload12416B is not reclaimed capacity. Address multiplication
uses i64 before physical page strides. Sources are BF16 vectors and the encoder
creates a new destination; it never compresses overlapping live K storage.

Device compilation/execution must be explicitly opted into a later completed
entry point. Actual TTGIR/LLIR/ASM/cubin must be retained and checked for K32,
logical M8, real score casts, complete native C chains and post-launch loaded
resources. The expected four I8 MMAs are currently a source-supported prediction;
unknown compiler/resource facts are not passes. No GPU, performance or service
qualification has run. All target jobs remain under the root agent's serial plan.

Any future service change requires every writer and all2D/3D consumers, current
Q32/multi2/generic prefill, prefix/suffix/carry/copy, typed ownership, metadata and
Graph to agree on the representation. BF16 wrapper metadata cannot identify raw
codes. Existing mode2 or a decoder-only hook does not implement that contract.
Any component tolerance is separate from intended quantization error and the
105-question/model/official throughput gates.
