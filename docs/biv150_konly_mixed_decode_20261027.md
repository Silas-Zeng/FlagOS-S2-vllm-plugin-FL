# Private mixed decode reader experiment

This tools/docs-only experiment starts from successfully fetched and API-verified team maindac1b8f (PR84 LM-head temperature fusion). It depends on PR79/80/82. No production source, writer, allocator, dispatch, service or official SDK is changed. Default CPU contracts import no Torch/Triton/NumPy/vLLM. Device compilation/numerics and service performance remain unverified; the first source freeze is shared early as Draft while the separate opt-in device entry is prepared. Nothing is queued by this author.

The actual main `biv150_mixed_decode.py` is a host **natural leading-prefix splitter**, not a separate Triton reader: `_prefix` accepts initial qlen1 sequences and `forward` slices that prefix into pure GQA. SDK54c495 selects2D whenever max qlen>1. SDK generic `reduce_segments` indexes partials by query token, whereas the backend's allocated partial capacity is seq_threshold3D rows. Blindly using a large `cu_q[seq]` as its scratch row would exceed that capacity. Main's existing profiler recorded8 mixed steps without a GQA launch and did not record the exact failed split predicate; no cause or end-to-end speedup is assumed here.

The new private mapping has two arms: BF16 control and packed K8/native I8-QK. Both derive the original main GQA producer/reducer and retain its softmax, BF16 P/V/PV, full/tail loops, accumulator expressions, reducer and strides. The K8 QK/codec dependency is copied byte-identically from actual tested PR79 sourcef287; new source still needs its own actual compilation/IR/numeric proof. Q quantization is inline once per active split CTA in this first candidate; no preQ cost is hidden.

Every producer/reducer CTA first checks sequence bounds, reads `cu_q[seq:seq+2]` as INT64 and returns unless qlen==1 with bounded nonnegative token coordinates. Q loads and output stores use q_start. **All partial/max/sum rows retain compact seq indexing**, including the original producer `token_idx=seq_idx`; no totalQ-sized partial allocation is introduced. qlen0 padding and qlen>1 prefill rows are untouched by both arms. All dynamic metadata is device scalar data, not host `.item()` reads. CPU lexical guard proofs are not actual target CFG proofs.

The factory exactly reverses the metadata mapping, then reverses the inherited K8 QK transformation to the original main kernel. The shared reducer reverses byte-for-byte to36859968. Mutation of a partial index, Q/output scatter, accumulator math or metadata span is refused. This verifies source invariants only; actual FMA/PV C chains, branch placement, typed ABI, native instruction counts and loaded resources remain unknown until root's explicit device validation.

K8 retains the versioned16KiB physical page: Kcode bytes0..4095, FP32 Kscale bytes4096..4223, original BF16 V bytes8192..16383. The scale pointer addresses the **full-page FP32 base**, with field offset1024 FP32 elements. K uses byte strides16384/256/128; V uses BF16-element strides8192/256/128. Page IDs are promoted before address multiplication, preserving offsets above2**43. Encoding requires separate source/destination buffers; format cannot be inferred from a BF16 wrapper dtype. Unknown format IDs are rejected. Descriptor contracts do not authenticate a production payload tag; PR82 integration must supply that contract. Physical capacity is not reclaimed.

Fixed totalQ2048 cases are `[1]*63+[1985]` at KV4096 and `[1]*31+[2017]` at KV16384. CPU proof also covers prefill-first/interleaved order (q_start≠seq), small tails, padded zero query lengths, empty decode KV, no decode rows, strided Q, all4096 per-page code coordinates, and valid int32 high page IDs whose addresses require INT64. Independent scalar INT64 dots and original/quantized-operand FP64 attention goals cover lengths0/1/15/16/17. They do not simulate GPU rounding, FTZ or MMA behavior.

Future coordinated execution must make the paired prefill reader **skip qlen1 rows**, so the mixed decode reader and prefill reader own disjoint output sets. No duplicated computation/output overwrite or stock-BF16 fallback may interpret an encoded K8 payload. The CPU partition contract rejects a paired prefill reader that does not skip these rows. No reader override or service activation is added now, and old prefill Q-hoist/resource proofs are not claimed for this new mapping.
